Visualisation d'une offre de stage

Parcours complet d'une liste d'offres : du rendu React au chargement HTTP, puis de l'authentification backend jusqu'à SQLite et au retour des données affichées dans le tableau.

Vue d'ensemble du workflow

La page ne décide pas quelles offres sont autorisées. Elle demande les offres avec le jeton de session ; le backend relit l'utilisateur en base, applique la règle de visibilité, puis renvoie uniquement les DTO exposables.

1. Déclenchement côté frontend

App.tsx et routage

Après connexion, App connaît l'utilisateur et son jeton. La route /offres est rendue seulement si canListOffers(user) est vrai pour l'interface.

OffersPage.tsx

La page transmet token et onUnauthorized à useOffers, puis choisit entre chargement, erreur, état vide et tableau. 

const { offers, isLoading, error } = useOffers(token, onUnauthorized);

if (error) return <ErrorState message={error} />;
if (isLoading) return <LoadingState />;
if (offers.length === 0) return <EmptyState ... />;
return <OfferTable offers={offers} />;

2. Appel HTTP et proxy de développement

Frontend
/api/offers → Proxy Vite retire /api → Backend
GET /offers

getOffers utilise fetch avec le signal d'un AbortController. L'en-tête Authorization contient le JWT sans préfixe Bearer. Le signal annule la requête si le composant est démonté ou si ses dépendances changent. 

fetch("/api/offers", {
  headers: { Authorization: token },
  signal,
});

3. Authentification et autorisation backend

Authentification

Le middleware authenticate lit l'en-tête, vérifie le jeton et recharge l'utilisateur depuis la base. Les rôles et les entreprises ne sont donc pas pris dans le contenu contrôlable du frontend.

401 UNAUTHENTICATED si la session est absente, invalide, expirée ou désactivée.

Autorisation

La route applique authorize(canListOffers). Les règles nommées se trouvent dans services/permissions.ts.

403 FORBIDDEN pour un contact qui n'a pas le rôle DEPOSITOR.

app.use("/offers", authenticate, createOffersRouter(offersService));

router.get("/", authorize(canListOffers), (req, res) => {
  res.json(offersService.listOffers(getCurrentUser(req)).map(toOfferDto));
});

4. Sélection des offres et lecture SQLite

Le service transforme le profil en filtre de repository avant toute lecture. Le repository utilise une requête paramétrée et joint companies, academic_years et periods.

Profil Filtre appliqué Résultat
Administrateur {} Toutes les offres, tous statuts confondus.
Étudiant status = PUBLISHED Uniquement les offres publiées.
Contact déposant depositor_contact_id = user.id Ses offres, quel que soit leur statut.
Contact sans rôle déposant Aucune requête métier 403 accès refusé.

Le tri SQL est déterministe : année académique la plus récente d'abord, puis offres les plus récemment créées. Les paramètres absents sont transmis comme NULL, ce qui désactive le filtre associé. 

SELECT o.id, o.title, o.description, o.status,
       c.short_name AS company_short_name,
       ay.label AS academic_year_label, p.code AS period_code
FROM offers o
JOIN companies c ON c.id = o.company_id
JOIN academic_years ay ON ay.id = o.academic_year_id
JOIN periods p ON p.id = o.period_id
WHERE (@status IS NULL OR o.status = @status)
  AND (@depositorContactId IS NULL OR o.depositor_contact_id = @depositorContactId)
ORDER BY ay.start_date DESC, o.created_at DESC;

5. Mapping et retour de la réponse

DBO → objet métier

toOffer convertit les noms SQL en propriétés TypeScript et regroupe les informations d'entreprise.

Objet métier → DTO

toOfferDto ne renvoie que les champs nécessaires à la liste : identifiant, titre, entreprise, année, période et statut. La description et les identifiants internes restent côté serveur.

Sur le frontend, readJson vérifie d'abord le statut HTTP puis isOfferList valide la forme du JSON. Une réponse inattendue produit une erreur explicite au lieu d'être utilisée comme si elle était valide.

6. Affichage final

Le hook stocke la liste dans son état. OffersPage la transmet à OfferTable, qui affiche chaque offre dans une ligne. Les codes techniques sont traduits en français par les helpers de utils/labels.ts : par exemple P2 devient « Février à mai » et PUBLISHED devient « Publiée ». 

<OfferTable offers={offers} />

<td>{offer.title}</td>
<td>{offer.companyShortName}</td>
<td>{offer.academicYear}</td>
<td>{PERIOD_LABELS[offer.period]}</td>
<td>{OFFER_STATUS_LABELS[offer.status]}</td>

États et erreurs traversants

Situation Backend Frontend
Chargement en cours Requête en traitement LoadingState
Session invalide 401 UNAUTHENTICATED Appel de onUnauthorized, retour à la connexion.
Droit insuffisant 403 FORBIDDEN Erreur affichée si la requête est tout de même tentée.
Liste vide 200 [] EmptyState « Aucune offre à afficher. »
Erreur inattendue 500 INTERNAL_ERROR et journalisation serveur ErrorState avec le message de chargement.
