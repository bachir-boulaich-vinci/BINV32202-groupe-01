Inventaire des guides et senseurs de Gesta

Classement des mécanismes selon leur rôle (guide ou senseur) et leur nature (inférentielle ou computationnelle). Survolez un mécanisme souligné pour voir le fichier ou l’outil dans lequel il est défini ou utilisé.

Méthode et état global

Guide

Décrit, demande ou impose une manière de développer, tester ou utiliser le projet.

Senseur

Observe, valide, refuse ou signale un état incorrect.

Inférentiel

Fondé sur une règle métier, une intention ou une interprétation humaine.

Computationnel

Exécuté automatiquement par un outil, le compilateur, SQLite ou le runtime.

Vérification de la séance : npm run check a réussi depuis la racine du dépôt. Oxlint, TypeScript, les tests backend et frontend, ainsi que les builds backend et frontend ont tous terminé avec succès. Les tests ont donné 126 tests backend et 51 tests frontend passés.

Senseurs inférentiels

Évaluation de règles métier ou de sécurité dans le code applicatif.

MécanismeFichier ou outilCe qu’il vérifieExemple de résultatÉtat
Règles de permissions backend/src/services/permissions.ts Détermine si un utilisateur est administrateur ou peut consulter les offres. Un contact promoteur/signataire sans déposant ne peut pas lister les offres. Testé
Authentification métier backend/src/middlewares/authenticate.ts Vérifie qu’une requête possède un utilisateur courant valide. Une session absente ou invalide produit 401 UNAUTHENTICATED. Testé
Autorisation métier backend/src/middlewares/authorize.ts Applique une règle de droit après authentification. Une règle qui retourne false produit 403 FORBIDDEN. Testé
Filtrage métier des offres backend/src/services/offers.service.ts Détermine les offres visibles selon le profil connecté. L’étudiant voit les offres publiées ; le déposant voit ses offres. Testé
Règles de configuration backend/src/config.ts Vérifie les invariants de démarrage et de sécurité. Le mode démo est refusé avec NODE_ENV=production. Testé indirectement
Vérification des jetons backend/src/utils/token.ts Vérifie signature, algorithme, durée et structure du JWT. Un jeton avec un kind inconnu est rejeté. Testé
Type guards frontend frontend/src/utils/guards.ts Détermine si un JSON correspond au modèle attendu. { status: "ok" } est accepté ; { status: "ko" } est refusé. Testé

Senseurs computationnels

Contrôles automatisés qui calculent un verdict sur le code, les données ou l’environnement.

MécanismeFichier ou outilCe qu’il contrôleExemple de résultatÉtat
Garde de version Node backend/src/nodeVersion.ts Vérifie la compatibilité avec better-sqlite3. Node 22.13.1 est refusé ; Node 22.14.0 est accepté. Testé
Garde de démarrage Node backend/src/requireSupportedNode.ts Arrête le processus avant le chargement de SQLite si Node est trop ancien. Affiche un message puis appelle process.exit(1). Testé indirectement
Validation des variables d’environnement backend/src/config.ts Valide port, secret JWT, mode démo et environnement. Un port nul, négatif, non entier ou supérieur à 65535 provoque une erreur. Testé indirectement
Contraintes SQLite backend/src/db/migrations/001_initial.sql Vérifie types stricts, clés étrangères, unicités et contraintes CHECK. Une offre avec status = "Publiée" ou un titre vide est refusée. Testé
Tests de migration backend/tests/db/migrations.test.ts Vérifient l’application correcte et unique des migrations. Une migration est enregistrée dans schema_migrations. Exécuté
Tests de seed backend/tests/db/seed.test.ts Vérifient la cohérence des données initiales. Les identifiants de seed permettent de construire des scénarios valides. Exécuté
Tests API backend backend/tests/ Vérifient réponses HTTP, erreurs, droits, filtres et scénarios métier. Une requête sans session reçoit 401 ; un droit insuffisant reçoit 403. 126 passés
Tests frontend frontend/tests/ Vérifient rendu React, interactions, hooks et réponses API simulées. Une réponse API invalide déclenche l’état d’erreur attendu. 51 passés
Oxlint oxlint --deny-warnings Analyse statiquement le code et les règles React/TypeScript. Le contrôle échoue en présence d’un any ou d’un avertissement. Exécuté
TypeScript tsc --noEmit et tsc -b Vérifie les types, imports et variables inutilisées. Une propriété potentiellement absente est signalée par le compilateur. Exécuté
Build backend backend/package.json Compile TypeScript et copie les migrations vers dist. tsc -p tsconfig.build.json termine sans erreur. Exécuté
Build frontend vite build Compile TypeScript et produit les assets de production. Vite a transformé 61 modules et généré frontend/dist. Exécuté

Limites de la vérification

  • Les commandes lint, typecheck, tests et build ont été exécutées dans cette séance.
  • Les requêtes REST de backend/http/ n’ont pas été lancées avec un client HTTP.
  • Le serveur backend et le navigateur n’ont pas été démarrés séparément dans cette séance.
  • Les documents de spécification et d’architecture sont des guides ; leur contenu est couvert seulement lorsque des tests correspondants existent.
  • La première tentative de npm run check depuis le dossier parent a échoué faute de package.json à cet emplacement ; la seconde, depuis la racine réelle du projet, a réussi.
